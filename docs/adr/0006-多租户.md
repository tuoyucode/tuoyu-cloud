# ADR 0006：多租户

| 项 | 内容 |
|---|---|
| 状态 | **已确认**（2026-10-28，第 9 节的决定由维护者确认）；实现与本文同时完成 |
| 关联 | ADR 0005（上下文透传 `ContextPropagator`、跨模块调用） |
| 适用 | 新模块 `tuoyu-common-tenant`（原创编写，CONTRIBUTING.md 基本规则第 1 条）；`tuoyu-common-mybatis`（`TenantEntity`、`@TenantIgnore`）；tuoyu-system（租户、租户套餐、表结构迁移 V3）；tuoyu-auth（登录先确定租户）；tuoyu-resource（文件目录、推送）；tuoyu-workflow（Warm-Flow 的租户）；前端租户管理与登录 |

## 1. 目标

- 共享表、按 `tenant_id` 字段隔离（1.0 只做这一种，预留独立 schema / 独立库的扩展点）；
- **默认关闭**（`tuoyu.tenant.enabled=false`）：关闭时不加载 SQL 拦截器，行为与单租户系统完全相同；
- 隔离覆盖：SQL、缓存、跨线程、跨服务（签名）、定时任务、文件目录、消息推送、工作流；
- 管理能力：租户、租户套餐（可用菜单的集合）；平台管理员可以切换进入某个租户；
- 跨租户越权测试进入 CI。

## 2. 表结构（已确认：表中始终有 `tenant_id`）

**隔离的表**都有 `tenant_id varchar(20) not null default 'default'`，并加索引。开关只决定是否按它过滤，所以以后打开多租户不需要改表、不需要迁移数据；关闭时新数据自动属于默认租户 `default`。

| 按租户隔离 | 平台共享（没有 `tenant_id`） |
|---|---|
| `sys_user`、`sys_role`、`sys_dept`、`sys_post`、`sys_notice`、`sys_message`、`sys_oper_log`、`sys_login_info`、`sys_social`、`sys_oss` | `sys_menu`、`sys_dict_type`、`sys_dict_data`、`sys_config`（已确认：字典与参数平台共享）、`sys_client`、`sys_oss_config`、`gen_table`、`gen_table_column`、新增的 `sys_tenant`、`sys_tenant_package` |

- 关联表（`sys_user_role`、`sys_role_menu`、`sys_role_dept`、`sys_user_post`、`sys_tenant_package_menu`）不加 `tenant_id`：主键都是雪花 ID，两端的记录已按租户隔离，只会被所在租户的数据引用；
- Warm-Flow 的 `flow_*` 表自带 `tenant_id`，通过 Warm-Flow 的租户扩展点接入（第 6 节）；
- SnailJob 的 `sj_*` 表不隔离：任务定义是平台级的，按租户执行由 `@TenantJob` 完成（第 6 节）。

新增的表：

| 表 | 字段（要点） |
|---|---|
| `sys_tenant` | `tenant_id`（主键，租户编码，小写字母、数字、连字符，2 ~ 20 位）、`tenant_name`、`contact_user`、`contact_phone`、`domain`（绑定的访问域名，可空，唯一）、`package_id`、`expire_time`（可空表示不过期）、`account_count`（可空表示不限）、`status`、审计字段 |
| `sys_tenant_package` | `package_id`、`package_name`、`status`、`remark`、审计字段 |
| `sys_tenant_package_menu` | `package_id`、`menu_id` |

由 Flyway 迁移 `V3__tenant.sql`（MySQL、PostgreSQL 各一份）完成：加字段、建表、种子数据（默认租户 `default` 不属于任何套餐，即可以使用全部菜单）、“租户管理”菜单。Oracle 改全新安装脚本，并新增升级目录。

## 3. 哪些数据按租户过滤

**约定**：实体对应的表有 `tenant_id` 字段（实体有 `tenantId` 属性，通常继承 `TenantEntity`），这张表就按租户隔离；**不需要**手工维护表清单。

- 在 Mapper 的类或方法上标注 `@TenantIgnore` 豁免（例如按用户名跨租户检查、平台统计）；
- 代码中用 `TenantHelper.ignore(...)` 临时忽略，用 `TenantHelper.dynamic(tenantId, ...)` 临时切换到某个租户执行；
- SQL 改写使用 MyBatis-Plus 的租户插件（查询、更新、删除加条件，插入补字段），本项目只提供“当前租户是谁、哪些表要隔离”；
- **缺少租户时拒绝执行（失败闭合）**：开启多租户后，访问隔离表的 SQL 如果既没有当前租户、也不在忽略范围内，直接报错，而不是查出全部租户的数据。后台任务必须用 `@TenantJob` 或 `TenantHelper` 明确租户。

## 4. 当前租户怎么确定

按优先级：

1. **显式指定**：`TenantHelper.dynamic(...)` 代码块中（登录时、`@TenantJob` 中）；
2. **平台管理员切换**：超级管理员调用“切换租户”后，Redis 中按用户记录要进入的租户（`tenant:dynamic:<userId>`，随登录过期），之后的请求在该租户中执行；“退出切换”后恢复；
3. **登录用户所属的租户**：登录时写入会话（`LoginUser.tenantId`）。

`TenantContext` 的实现在 `tuoyu-common-tenant` 中，其他框架模块只依赖接口。

## 5. 登录（已确认：用户名在租户内唯一，登录先确定租户）

- 登录、注册、短信 / 邮箱登录的请求体增加 `tenantId`；
- 前端先按访问域名查询租户（`GET /auth/tenant/list?domain=...`，免登录）：开启多租户时返回 `enabled: true` 与可选择的租户（域名匹配时只返回该租户并锁定）；关闭时返回 `enabled: false`，登录页不显示租户；
- 后端：开启多租户时，`tenantId` 为空则拒绝；校验租户存在、启用、未过期后，在 `TenantHelper.dynamic(tenantId, ...)` 中查询用户。用户名唯一性检查本来就在服务代码中查询，加上租户条件后即为租户内唯一；
- 登录失败锁定的键加上租户（同名用户在不同租户中分别计数）。

## 6. 跨线程、跨服务与其他组件

| 组件 | 做法 |
|---|---|
| 跨线程 | `TenantPropagator` 实现 ADR 0005 的 `ContextPropagator`；Spring 的异步执行器通过 `TaskDecorator` 包装任务，在执行线程中恢复租户与数据权限状态（不引入 TransmittableThreadLocal）。跨线程的值只在本进程内存中传递，不签名、不设有效期（`captureLocal` / `restoreLocal`，键与跨服务不同） |
| 跨服务 | 同一个 `TenantPropagator` 经 Dubbo 附件透传，值为 `租户|忽略标记|时间戳|HMAC-SHA256`，密钥 `TUOYU_TENANT_CONTEXT_SECRET`；提供方**验签通过才采信**，签名错误、过期（默认 60 秒）时拒绝调用。开启多租户时密钥必填，缺少时拒绝启动。没有显式租户时不透传，提供方从登录令牌得到用户所属租户 |
| 缓存 | 开启后，Spring Cache 中按租户隔离的缓存，键加 `租户:` 前缀；字典、参数、菜单、客户端等平台共享的缓存不加（`tuoyu.tenant.global-caches` 可调整） |
| 定时任务 | 执行器方法标注 `@TenantJob`：依次在每个启用且未过期的租户中执行一次，单个租户失败只记录日志，不影响其他租户 |
| 文件 | 开启后，上传文件的对象路径加租户前缀（`<tenantId>/...`） |
| 消息推送（SSE / WebSocket） | 按用户推送不受影响（用户 ID 全局唯一）；“推送给所有人”只推送给同一租户的在线用户 |
| 工作流 | 实现 Warm-Flow 的租户扩展点，返回当前租户 |

## 7. 管理能力

- **租户套餐**：可用菜单的集合。租户内所有角色只能分配套餐中的菜单；默认租户不属于任何套餐，可以使用全部菜单；
- **租户**：新增租户时，同时创建该租户的根部门、管理员角色（拥有套餐中的全部菜单）、管理员账号（账号口令由平台管理员填写，口令走 `@ApiEncrypt`）；修改套餐后，同步租户管理员角色的菜单；停用或过期的租户不能登录；
- **平台管理员**：默认租户中的超级管理员管理租户与套餐，并可以切换进入某个租户查看与维护；租户内的用户看不到这些菜单；
- 关闭多租户时，“租户管理”菜单与登录页的租户选择都不显示（菜单接口按开关过滤）。

## 8. 测试（CI 必跑）

1. **SQL 改写**：开启时，查询、更新、删除隔离表都带上当前租户条件，插入补上租户；共享表不变；`@TenantIgnore` 与 `TenantHelper.ignore` 生效；缺少租户时拒绝；
2. **签名透传**：篡改租户或签名、过期的上下文被拒绝；
3. **越权（Testcontainers，真实 MySQL）**：两个租户各有数据，租户 A 的查询、按 ID 查询、更新、删除都碰不到租户 B 的数据；
4. 登录：开启时不带租户被拒绝，租户停用、过期被拒绝；
5. 关闭时：不加载拦截器，SQL 不变。

## 9. 决定（2026-10-28 维护者确认）

| # | 问题 | 决定 |
|---|---|---|
| T1 | 租户字段怎么放 | 隔离的表**始终**有 `tenant_id`，开关只控制是否过滤（不采用“关闭时实体不需要 tenant_id”的做法） |
| T2 | 用户名唯一范围与登录 | 租户内唯一；登录先确定租户（域名识别，识别不到时选择或输入） |
| T3 | 字典与参数 | 平台共享，1.0 不按租户隔离 |

## 10. 后果与已知限制

- 关闭时零开销（没有拦截器）；开启后，后台代码必须明确租户（失败闭合），这是有意的约束；
- 字典、参数平台共享：租户不能自定义自己的字典（1.x 再评估）；
- 独立 schema / 独立库的租户模式不在 1.0 范围；
- MQ（RabbitMQ 等）的租户透传不在 1.0 范围，Redis Stream（Bus）事件随事件内容携带租户。

## 11. 实施记录（2026-10-29）

| 项 | 结果 |
|---|---|
| 隔离表的识别 | 按 MyBatis-Plus 已解析的实体中是否有映射到 `tenant_id` 的普通字段判断；`sys_tenant` 的 `tenant_id` 是主键，不计入，所以租户表本身不会被隔离 |
| **插入与更新时伪造租户**（实施中发现） | MyBatis-Plus 的租户插件在插入语句已有 `tenant_id` 列时直接采信实体中的值，按实体更新时也会把 `tenant_id` 写入 SET，可以把数据写进或“搬”到其他租户。框架的字段填充（`InjectionMetaObjectHandler`）在开启多租户、有当前租户时：插入一律改写为当前租户。`TenantEntity.tenantId` 标注为插入时填充、更新策略为 NEVER（按实体生成的 UPDATE 语句中没有 `tenant_id`）。忽略租户的代码块中，插入保留实体中的值。最初的做法是更新填充时把 `tenantId` 置空，但 MyBatis-Plus 在填充之前就按字段是否为空决定了 SET 子句，结果写入 null、违反非空约束：开启多租户后，“先查出再按实体更新”的写法全部失败。CI 中真实 MySQL 上的越权测试首次执行时发现，已改为更新策略 |
| `@TenantIgnore` | 用 Spring AOP 实现（`TenantIgnoreAdvisor`），可以标注在 Mapper 的默认方法、Service 方法或类上 |
| 透传的内容 | 透传**解析后的当前租户**（不只是显式指定的）：`@Async` 线程与虚拟线程中没有登录请求，取不到用户所属的租户，按失败闭合会拒绝执行 |
| 跨线程 | `TaskDecorator`（`tuoyu-common-rpc`，作用于 Spring Boot 自动配置的执行器）与 `ThreadUtils` 的两个虚拟线程方法都会恢复提交时的上下文；没有引入 TransmittableThreadLocal。最初跨线程与跨服务共用带签名与 60 秒有效期的值，`@Async` 任务排队超过 60 秒会因“租户上下文已过期”失败；2026-11-02 改为跨线程单独透传（`ContextPropagator.captureLocal` / `restoreLocal`），不设有效期；跨服务收到这些键时不采信 |
| 登录 | `TenantLoginGuard`（tuoyu-auth）校验租户后在 `TenantHelper.dynamic` 中执行登录、注册；`/auth/tenant/list` 返回开关与可选租户；登录失败锁定的键加上租户 |
| 菜单 | `TenantMenuScope`：租户内的菜单、权限码与套餐取交集（套餐缩小后多出的权限立即失效）；角色授权时服务端校验菜单必须在套餐内；关闭多租户时隐藏 `system:tenant*` 菜单 |
| 消息推送 | 通知公告在开启多租户时改为推送给本租户的全部用户（按用户推送天然隔离），推送模块不改 |
| 文件 | 上传的对象路径以租户为业务前缀 |
| 工作流 | `WarmFlowTenantHandler` 返回当前租户 |
| 租户的维护 | 用户数上限：新增、导入、注册用户前检查（`TenantAccountQuota`，并发时可能短暂超出 1 ~ 2 个）；修改时过期时间、用户数上限为空即清除（改为“不过期”“不限”）；默认租户（平台）可以修改名称、联系人、域名等，没有套餐、不能停用，修改时忽略这两项 |
| 表结构 | `V3__tenant.sql`（MySQL、PostgreSQL）；Oracle 改全新安装脚本并新增 `deploy/sql/upgrade/20261029-tenant` |
| 测试 | 单元测试 19 个（SQL 改写与失败闭合、签名透传、缓存隔离、`@TenantJob`、插入与更新时的租户字段、用户数上限）；真实 MySQL 上的越权测试 5 个（Testcontainers，本机跳过，CI 必跑） |
| 尚未验证 | 开启多租户后的端到端流程（新增租户、租户管理员登录、套餐菜单、超级管理员切换）需要启动服务后验证；前端页面见前端仓库 |
