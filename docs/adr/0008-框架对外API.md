# ADR 0008：框架对外 API

| 项 | 内容 |
|---|---|
| 状态 | **已采纳**（2026-11-07）：第 9 节的取舍由维护者确认，已按本文实施 |
| 关联 | ADR 0001（接口加密，响应加密包裹整个响应体）、ADR 0005（`UserContext`、`CurrentUser`）、ADR 0007（traceId） |
| 适用 | `tuoyu-common-core`、`tuoyu-common-web`、`tuoyu-common-mybatis`、`tuoyu-common-satoken`、`tuoyu-common-log`、`tuoyu-common-redis`；全部业务模块与网关；代码生成模板；前端请求层与各页面；`tuoyu-e2e` |
| 时机 | 1.0 发布前完成。发布后这些类型会出现在使用者的业务代码里，再改就要提供升级路径 |

## 1. 背景

业务代码每天接触的框架类型，现在分散在几种风格里：

- **响应**：`R<T>`（`code`、`msg`、`data`），未登录、无权限也返回 HTTP 200，靠 `code` 区分，前端要在拦截器里把 `code: 401` 转成 401；响应中没有 traceId，排查问题时要另看响应头。
- **分页**：请求参数 `pageNum`、`pageSize`、`orderByColumn`、`isAsc`（排序字段与方向分成两个参数，只支持一个字段）；结果 `PageResult<T>` 的 `rows`、`total`。
- **当前用户**：同时有两套入口：`tuoyu-common-satoken` 的静态工具 `LoginHelper`（39 个文件）与 core 的 `UserContext` / `CurrentUser`（9 个文件，ADR 0005 引入，供 mybatis 等不依赖 Sa-Token 的模块使用）。同一件事两种写法。
- **持久层**：`BaseMapperPlus<T, V>` 在 Mapper 上提供 `selectVoById`、`selectVoPage` 等直接返回 Vo 的方法（33 个文件），Mapper 同时负责查询与对象转换。
- **对象转换**：`MapstructUtils.convert`，是 mapstruct-plus `Converter` 的静态包装。
- **写操作的返回**：服务返回 `boolean` / `int`，Controller 继承 `BaseController` 用 `toAjax(...)` 把它转成成功或失败；失败时只有一句笼统的“操作失败”，真正的原因丢失。
- **其他**：校验分组 `AddGroup` / `EditGroup` / `QueryGroup`；操作日志 `@Log(title, businessType)` 与枚举 `BusinessType`；防重复提交 `@RepeatSubmit`。

## 2. 目标与非目标

目标：

- 业务开发者接触的类型只有一套写法，名称说明用途；
- HTTP 语义正确：错误类别由 HTTP 状态码表达，网关、反向代理、监控能直接按状态码统计；
- 每个响应都能对上日志（traceId）；
- 分层清楚：Mapper 只管实体，转换在服务层；
- 代码生成模板、前端、端到端测试与新 API 同步。

非目标（1.x 再改写）：

- 通用工具类（`StringUtils`、`StreamUtils`、`SpringUtils`、`ServletUtils` 等）、常量类、`ServiceException`、`RedisUtils` / `CacheUtils`、Excel、会话模型 `LoginUser`；
- 实体审计字段（`createBy`、`createTime` 等）的名称：它们对应数据库列，随 SQL 基线一起考虑。

## 3. 响应

```json
{ "code": 0, "message": "操作成功", "data": { }, "traceId": "4bf92f3577b34da6a3ce929d0e0e4736" }
```

- 类型 `ApiResult<T>`（不叫 `Result`：Dubbo 有 `org.apache.dubbo.rpc.Result`），在 `tuoyu-common-core`；静态方法 `ok()`、`ok(data)`、`ok(message, data)`、`fail(code, message)`；
- `code`：成功为 `0`；失败时默认等于 HTTP 状态码，业务异常可以带自己的错误码（`ServiceException` 已有 `code`）。HTTP 状态由 `ApiResult.httpStatus()` 确定：code 在 400 ~ 599 之间时就是它，否则（业务自定义错误码、`ServiceException` 没有错误码）为 400；
- `traceId`：取当前链路（ADR 0007），成功与失败都带。core 不依赖链路追踪模块：Spring MVC 内由 `tuoyu-common-web` 的 `ApiResultAdvice` 在写出前填入；在 Spring MVC 之外写出错误响应的过滤器（请求大小限制、服务的登录校验）通过 core 中的 `TraceIdSource`（由 `tuoyu-common-observability` 注册）取得；网关直接读 `TraceContext`；
- Controller 不返回失败的 `ApiResult`，失败时抛 `ServiceException`；直接返回时 `ApiResultAdvice` 按 code 设置 HTTP 状态，保证失败一定是 4xx / 5xx；
- **HTTP 状态码表达错误类别**，由全局异常处理（`GlobalExceptionHandler` 与各模块的 `*ExceptionHandler`、网关的 `GatewayExceptionHandler`）与过滤器统一映射：

| 情况 | HTTP 状态 |
|---|---|
| 成功 | 200 |
| 参数校验失败、请求格式错误、业务规则不满足（`ServiceException` 没有错误码或为自定义错误码、`UserException` 等） | 400 |
| 未登录、令牌失效 | 401 |
| 无权限、无角色、租户不允许、客户端不允许访问的路径 | 403 |
| 资源或路径不存在 | 404 |
| 请求方式不支持 | 405 |
| 数据重复（唯一键冲突） | 409 |
| 请求过大（已有） | 413 |
| 请求内容类型不支持 | 415 |
| 限流、重复提交、分布式锁获取失败（业务处理中） | 429 |
| 未预期的异常 | 500（只返回错误编号，详情按编号记日志，已有） |
| 下游没有实例（网关，已有） | 503 |

- 下载、导出等直接写响应流的接口不变；
- Warm-Flow 自带的接口（`/warm-flow/**`）供它自带的设计器使用，保持 Warm-Flow 自己的返回结构（成功时 `code` 为 200）；这些接口被权限校验拒绝时（ADR 0005 中的 `WarmFlowAccessInterceptor`）返回本文的统一结构；
- 自己写 `@RestControllerAdvice` 或在过滤器中直接写出错误时，用 core 的 `ApiErrors` 生成响应，保证结构、HTTP 状态与 traceId 一致。模块专用的异常处理类标 `@Order(ExceptionHandlerOrder.MODULE)`，排在全局异常处理（`ExceptionHandlerOrder.GLOBAL`）之前，不依赖自动配置的加载顺序；
- 过滤器链中抛出、没有被异常处理接住的异常与 `sendError`，由容器转到错误页面：各服务用 `tuoyu-common-web` 的 `ApiErrorController`、网关用 `GatewayErrorController` 代替 Spring Boot 默认的错误控制器，返回同样的结构（不带异常消息，500 只返回错误编号）；
- 接口加密（ADR 0001）对整个响应体加密，结构变化不影响协议；加密失败的提示按新的 `message` 字段读取。

## 4. 分页

请求参数：

| 参数 | 说明 |
|---|---|
| `page` | 页码，从 1 开始，默认 1 |
| `pageSize` | 每页条数，默认 10，上限 `tuoyu.page.max-size`（已有） |
| `sort` | 排序，格式 `字段,asc` 或 `字段,desc`，可重复传多个；字段名按实体属性校验，不在实体中的一律拒绝，排序列只能来自实体属性；敏感属性（口令、密钥类，不下发、加密或脱敏的字段）不能排序，否则可借排序结果推出看不到的值 |

- 类型 `PageParam`（不叫 `PageRequest`：Spring Data 有同名类），在 `tuoyu-common-mybatis`；`toPage(实体类)` 转成 MyBatis-Plus 的分页对象，排序属性按实体的表信息映射为列名（联表时可加表别名），不按实体查询的列表用 `toPage()`（不支持排序）或显式的排序白名单；`PageParam.countOnly()` 保留（导出前统计，见 CONTRIBUTING“Excel 行数上限”）；
- 只传一个 `sort=createTime,desc` 时 Spring 会按逗号把它拆成两项，`PageParam` 按“属性名后可跟一个方向”的顺序解析，与传多个 `sort` 的结果相同；
- 结果 `PageResult<T>`（core）：`{ "items": [...], "total": 123 }`，`PageResult.of(items, total)`、`PageResult.empty()`；从 MyBatis-Plus 的分页结果转换用 mybatis 模块的 `PageResults.of(page)`、`PageResults.of(page, mapper)`、`PageResults.of(page, Vo.class)`（core 不依赖 MyBatis-Plus）。

## 5. 当前用户

- 业务代码只用 core 的 `UserContext`，改为静态入口：`UserContext.current()`（`Optional<CurrentUser>`）、`UserContext.require()`（未登录抛 401）、`UserContext.userId()`、`UserContext.userIdString()`、`UserContext.isLoggedIn()`、`UserContext.isSuperAdmin()`、`UserContext.isSuperAdmin(userId)`；
- 提供实现的 SPI 改名为 `UserContextProvider`，Sa-Token 模块实现它（与现在相同）。core 的自动配置在容器启动完成后把唯一的提供者设置给 `UserContext`，关闭时撤销；测试中用 `UserContext.setProvider(...)` 替换。框架模块（数据权限、审计字段填充、多租户）仍通过容器注入提供者；
- `CurrentUser` 按现有 `LoginHelper` 的调用补上字段：昵称、用户类型、部门类别、客户端、设备类型、浏览器、操作系统、角色权限字符串（`roleKeys`）、菜单权限码（`permissions`）；
- `LoginHelper` 只留在 `tuoyu-common-satoken` 与 auth 内部，处理登录、登出与会话，其他模块不引用（ArchUnit 规则，ADR 0005 第 4 节第 6 条）；
- 需要读取**其他会话**中的登录用户时（在线用户管理、角色权限变更后让相关会话下线），用 `tuoyu-common-satoken` 的 `LoginSessions`，它不用于读取当前请求的用户。

## 6. 持久层与对象转换

- **Mapper 只管实体**：业务 Mapper 直接继承 MyBatis-Plus 的 `BaseMapper<T>`；`BaseMapperPlus` 与它的链式写法（`mapper.lambda()`）删除。批量插入、更新改用 MyBatis-Plus `BaseMapper` 自带的批量方法（`insert(Collection)`、`updateById(Collection)`、`insertOrUpdate(Collection)`）；链式条件用已有的 `QueryBuilder.lambda(实体类)` 构造，再调用 Mapper 的方法执行；
- **转换在服务层**：`BeanMapper.map(source, Target.class)`、`BeanMapper.map(source, target)`、`BeanMapper.mapList(list, Target.class)`，内部仍用 mapstruct-plus，空值安全（列表为空时返回空列表）；分页结果用 `PageResults.of(page, Vo.class)`；
- 数据权限（`@DataPermission`）、多租户、逻辑删除都在 MyBatis 拦截器中，不受 Mapper 基类变化影响；
- `@DataPermission` 由 Spring 代理在调用 Mapper 方法时设置，`BaseMapper` 的默认方法在 MyBatis 代理内部转调其他方法时不经过 Spring 代理（例如 `update(Wrapper)` 转调 `update(实体, Wrapper)`）。带数据权限的 Mapper 要把业务会调用的默认方法覆盖并加上注解，例如 `SysUserMapper` 的两个 `update`（`SysUserMapperDataPermissionTest` 覆盖这条路径）；
- `BaseEntity` 删除没有用到的 `searchValue`，其余字段不变。

## 7. Web 层与注解

| 原写法 | 新写法 | 说明 |
|---|---|---|
| `BaseController.toAjax(boolean / int)` | 删除 | 写操作的服务方法返回 `void`，失败时抛出带原因的 `ServiceException`；Controller 直接返回 `ApiResult.ok()` |
| `AddGroup` / `EditGroup` / `QueryGroup` | `OnCreate` / `OnUpdate` | 查询分组只有 3 处使用，删除 |
| `@Log(title, businessType)` + `BusinessType` | `@OperationLog(module, action)` + `AuditAction` | 操作日志表的存储值不变（`AuditAction.code()` 与 `BusinessType` 的序号相同）；常量用英文动词：`CREATE`、`UPDATE`、`DELETE`、`GRANT`、`EXPORT`、`IMPORT`、`FORCE_LOGOUT`、`GENERATE_CODE`、`CLEAN`、`OTHER` |
| `@RepeatSubmit` | `@PreventResubmit` | 重复提交返回 429；限流 `@RateLimiter` 超限同样返回 429 |
| 请求头名 `clientid` 在网关、日志、跨域配置中各写一份 | core 的 `HeaderNames.CLIENT_ID` | `LoginHelper.CLIENT_KEY` 引用它 |

## 8. 影响范围与实施

| 范围 | 内容 |
|---|---|
| 后端 | 使用 `R` 的约 50 个文件、65 个文件的分页参数、39 个文件的当前用户、33 个 Mapper 与对应服务、全局异常处理、网关的错误响应（与服务统一为同一结构） |
| 代码生成 | `java` 与 `vben` 模板按新 API 改写；`vue`（Element Plus）与 `react` 模板删除，它们面向的前端与本项目的接口契约不一致。已有业务表的前端模板类型由迁移 V7（Oracle 为升级目录 `20261107-gen`）统一为 `vben`；代码生成详情接口返回 `{ info, columns }` |
| 前端 | 请求拦截器（按 HTTP 状态处理错误）、`PageResult` 类型与使用 `rows` 的约 47 个文件、使用 `pageNum` 的约 29 个文件、排序参数 |
| 测试 | 单元测试随类型修改；`tuoyu-e2e` 与前端 Playwright 测试按新结构断言 |
| 远程接口 | `RemoteSocialService.deleteWithValidById`、`RemoteUserService.registerUserInfo`、`RemoteWorkflowService.completeTask`、`startCompleteTask` 改为没有返回值、失败时抛出带原因的异常（与写操作的服务方法一致）；`RemoteTaskAssigneeBo` 的页码字段为 `page` |
| 守护 | ArchUnit：`LoginHelper` 只在认证模块中使用；旧类型已删除，残留的引用在编译时即失败；`ControllerAuthAnnotationTest` 不变 |

实施顺序：core 与 mybatis 的新类型 → 全局异常处理与网关 → 业务模块逐个迁移 → 删除旧类型 → 代码生成模板 → 前端 → 端到端测试。每一步完整构建通过。

## 9. 已确认的取舍

1. **响应风格**：统一包装 `ApiResult` + HTTP 状态码表达错误类别。不采用“成功直接返回数据、错误用 RFC 9457（`ProblemDetail`）”：后者更标准，但与国内前端常见的统一包装习惯不同，前端与第三方调用方的改动更大。
2. **业务异常的状态码**：400。不用 422（部分代理、监控按 4xx 细分统计时不常见），也不保持 200 只看 `code`（与“HTTP 语义正确”的目标冲突）。
3. **Mapper 层**：删除 `BaseMapperPlus`，Mapper 只管实体，转换在服务层；不保留“Mapper 直接返回 Vo”的能力。
4. **代码生成**：只保留 `vben` 模板。
5. **命名**：`ApiResult`、`PageParam`、`PageResult`、`PageResults`、`UserContext` / `UserContextProvider`、`CurrentUser`、`BeanMapper`、`OnCreate` / `OnUpdate`、`@OperationLog` / `AuditAction`、`@PreventResubmit`、`ApiErrors`、`TraceIdSource`、`LoginSessions`、`HeaderNames`。按服务与单体的全部依赖（含间接依赖）扫描类路径，均不与依赖库中的类同名，以下两个已知的重名除外。
6. **已知的重名**：下列重名不会与本框架的类同时使用，予以保留：

| 本框架的类 | 依赖库中的同名类 | 所在依赖 | 无害的原因 |
|---|---|---|---|
| `org.tuoyu.common.core.domain.ApiResult` | `org.dromara.warm.flow.core.dto.ApiResult` | `warm-flow-core` | 只用于 Warm-Flow 自带的接口（`/warm-flow/**`）内部，项目中没有任何文件引用它 |
| `org.tuoyu.common.core.domain.PageResult` | `org.apache.seata.common.result.PageResult` | `seata-all` | Seata 控制台内部使用，项目中没有任何文件引用它 |

新增类型时同样先扫描类路径；新的重名只有在无法避免、且不会同时使用时才能保留，并登记在上表中。
