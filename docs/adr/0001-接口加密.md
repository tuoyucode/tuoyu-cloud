# ADR 0001：接口加密

| 项 | 内容 |
|---|---|
| 状态 | 已采纳（2026-10-23） |
| 适用 | 后端 `tuoyu-common-encrypt`；前端请求层 |

## 1. 背景

旧方案的问题：

1. **私钥下发到前端**：响应用后端的公钥加密，前端必须持有对应的私钥才能解密，任何人打开浏览器开发者工具都能拿到这把私钥。
2. AES 使用 ECB 模式，没有完整性校验；RSA 使用 PKCS#1 v1.5 填充，最低 1024 位。
3. 没有防重放：截获的登录请求可以原样重发。
4. 公钥写死在前端构建产物中，换密钥要重新构建前端。

## 2. 决定

- 正文用 **AES-256-GCM** 加密；AES 密钥用 **RSA-OAEP（SHA-256）** 加密。RSA 密钥建议 3072 位，低于 2048 位时服务拒绝启动。
- AES 密钥由**客户端为每个请求随机生成**。响应加密沿用这把密钥，因此**前端不持有任何私钥**。
- 公钥在运行时通过接口获取，用 `kid` 区分密钥，支持“当前 + 上一把”两把私钥同时有效，用于轮换。
- 请求带时间戳和随机数（nonce），**时间窗口 5 分钟**，nonce 在 Redis 中记录，防止重放。
- 浏览器在 HTTPS（或 `localhost`）下使用内置的 WebCrypto；`require-https` 关闭时，非 HTTPS 页面改用 JavaScript 加密库，协议完全相同。
- 旧方案（`api-decrypt.*`、`encrypt-key` 请求头）整体删除，**不保留兼容开关**。

## 3. 协议 v1

### 3.1 获取公钥

`GET /auth/crypto/public-key`，无需登录。

```json
{
  "code": 200,
  "data": {
    "enabled": true,
    "version": 1,
    "kid": "Qm9vdHN0cmFwS2V5",
    "algorithm": "RSA-OAEP-256+A256GCM",
    "publicKey": "MIIBojANBgkqhkiG9w0BAQEFAAOCAY8AMIIBigKCAYEA…",
    "requireHttps": true,
    "replayWindowSeconds": 300
  }
}
```

- `enabled`：为 `false` 时后端未开启接口加密，前端按明文发送，其余字段为空。
- `publicKey`：X.509 SubjectPublicKeyInfo（SPKI）DER 的标准 Base64，可直接用于 WebCrypto `importKey('spki', …)`。
- `kid`：SPKI 的 SHA-256 前 12 字节，Base64URL 无填充（16 个字符）。
- 前端可以缓存公钥；收到“请求解密失败”时应重新获取公钥再试一次（可能遇到了密钥轮换）。

### 3.2 加密请求

只支持 `POST`、`PUT`、`PATCH`。

请求头：

```
X-Tuoyu-Encrypted: 1
Content-Type: application/json
```

请求体（信封）：

```json
{
  "v": 1,
  "kid": "Qm9vdHN0cmFwS2V5",
  "key": "<Base64：RSA-OAEP 加密后的 32 字节 AES 密钥>",
  "iv": "<Base64：12 字节>",
  "ts": 1792738328000,
  "nonce": "<Base64：16 字节>",
  "data": "<Base64：AES-GCM 密文，末尾附 16 字节认证标签>"
}
```

| 步骤 | 说明 |
|---|---|
| 1 | 用安全随机数生成 32 字节 AES 密钥、12 字节 `iv`、16 字节 `nonce`；`ts` 取当前毫秒时间戳 |
| 2 | 附加数据 AAD = UTF-8 字符串 `tuoyu-api-crypto/v1/request|{kid}|{ts}|{nonce}`（`nonce` 为 Base64 文本） |
| 3 | `data` = AES-256-GCM（密钥、`iv`、AAD，标签 128 位）加密原始 JSON 的 UTF-8 字节 |
| 4 | `key` = RSA-OAEP 加密 AES 密钥；**哈希与 MGF1 均为 SHA-256**，标签为空 |

除特别说明外，Base64 一律为标准字母表、带填充。

### 3.3 服务端校验顺序

1. 信封格式、`v`、各字段长度；`kid` 必须是当前或上一把密钥；
2. RSA-OAEP 解出 32 字节 AES 密钥；
3. AES-GCM 解密并校验 AAD；
4. 时间戳与服务器时间相差不超过 5 分钟；
5. nonce 未被使用过（Redis 记录，保留 2 倍窗口时间）。

时间和 nonce 放在完整性校验之后检查，这样伪造的请求无法消耗 nonce，也无法探测服务器时间。

### 3.4 加密响应

接口标注 `@ApiEncrypt(response = true)` 且请求是加密请求时，响应也加密：

```
X-Tuoyu-Encrypted: 1
Content-Type: application/json
```

```json
{ "v": 1, "iv": "<Base64：12 字节>", "data": "<Base64：AES-GCM 密文 + 标签>" }
```

- 密钥：请求中客户端生成的 AES 密钥；`iv` 由服务端重新生成。
- AAD = `tuoyu-api-crypto/v1/response|{请求的 nonce}`。
- 解密后的内容就是平常的 `R` 返回结构。异常时的错误响应同样加密，前端以响应头 `X-Tuoyu-Encrypted` 判断是否需要解密。

### 3.5 错误

错误按项目统一的返回结构 `R` 返回（HTTP 状态 200，`code` 为 400），与其他业务错误的处理方式一致。

| 情况 | `code` | 提示 |
|---|---|---|
| 标注了 `@ApiEncrypt` 的接口收到未加密请求 | 400 | 该接口要求加密传输 |
| 信封格式错误、`kid` 未知、解密失败、认证标签不对 | 400 | 请求解密失败（具体原因只写日志） |
| 时间戳超出窗口 | 400 | 请求已过期，请检查本机时间是否准确 |
| nonce 已使用 | 400 | 请求已过期，请检查本机时间是否准确 |
| 在 `GET`、`DELETE` 等请求上使用加密 | 400 | 请求解密失败 |

## 4. 配置

```yaml
tuoyu:
  api-crypto:
    enabled: true
    # PKCS#8 DER 的 Base64；公钥由私钥推导，不需要单独配置
    private-key: ${TUOYU_API_CRYPTO_PRIVATE_KEY}
    # 轮换期间填写上一把私钥，轮换完成后清空
    previous-private-key: ${TUOYU_API_CRYPTO_PREVIOUS_PRIVATE_KEY:}
    # 是否要求浏览器使用 HTTPS
    require-https: ${TUOYU_API_CRYPTO_REQUIRE_HTTPS:true}
    replay-window: 5m
```

**密钥轮换**：执行 `java tools/secrets/GenerateEnv.java --api-crypto-key` 生成新私钥（只输出，不修改文件）→ 旧私钥移到 `previous-private-key`，新私钥填入 `private-key` → 重启服务 → 等前端缓存的旧公钥全部失效（建议 1 天）→ 清空 `previous-private-key`。

## 5. 前端实现要点

- **HTTPS 或 `localhost`**（`window.isSecureContext` 为真）：使用 WebCrypto，`RSA-OAEP` + `{ hash: 'SHA-256' }`、`AES-GCM` + `tagLength: 128`，不引入加密库。
- **非 HTTPS**：
  - `requireHttps` 为真：不发送请求，登录页提示“当前不是 HTTPS 访问，无法安全传输密码，请联系管理员配置 HTTPS”；
  - `requireHttps` 为假：按需加载 JavaScript 加密库，实现完全相同的协议。随机数仍使用 `crypto.getRandomValues`（非 HTTPS 下也可用）。
  - 加密库只能选 MIT、BSD、Apache 等宽松协议的库，例如 AES-GCM 用 `@noble/ciphers`（MIT），RSA-OAEP-256 用 `jsrsasign`（MIT）；只在非 HTTPS 时按需加载，不进入主包。
- **两条路径都必须通过同一份测试向量**：`tuoyu-framework/tuoyu-common-encrypt/src/test/resources/api-crypto/test-vectors.json`（其中的私钥仅用于测试，已列入启动自检的已公开密钥名单）。
- 需要加密的接口由前端请求配置标记；后端标注了 `@ApiEncrypt` 的接口目前有：登录、注册、修改密码、重置用户密码。

## 6. 安全边界

- 接口加密**不能替代 HTTPS**。它的作用是：密码不以明文出现在代理、网关、WAF 和访问日志中，满足“密码传输加密”的合规要求。
- 不使用 HTTPS 时，只能防住被动窃听；中间人可以替换前端代码或公钥。因此 `require-https` 默认开启，关闭后安全中心显示警告。
- 响应加密的密钥来自请求，所以只能用在加密请求上。
