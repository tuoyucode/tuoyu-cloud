# 升级指南：升级到 1.0.0-alpha.1

适用于已经按导入时的基线版本部署过、要升级到 1.0.0-alpha.1 的环境。全新安装不需要看本文，按 README 的快速开始即可。

**建议顺序**：备份数据库与 Nacos 配置 → 环境变量 → Nacos 配置 → 数据库 → 启动服务 → 前端。

## 1. 环境变量

对照仓库根目录的 `.env.example` 检查本地 `.env` 或部署环境：

| 变量 | 变化 |
|---|---|
| `TUOYU_API_CRYPTO_PRIVATE_KEY` | **新增，必填**：接口加密私钥。执行 `java tools/secrets/GenerateEnv.java --api-crypto-key` 生成 |
| `TUOYU_API_REQUEST_PRIVATE_KEY`、`TUOYU_API_RESPONSE_PUBLIC_KEY` | **删除**：旧的接口加密方案已移除；同时删除 `.env.frontend` |
| `TUOYU_DB_TYPE` | 新增，可选：`mysql`（默认）或 `postgresql` |
| `TUOYU_FIELD_ENCRYPT_KEY`、`TUOYU_FIELD_ENCRYPT_LEGACY_PASSWORD` | 开启字段加密时必填新密钥（`GenerateEnv --field-key`）；有升级前加密的旧数据时填旧口令，用于解密 |
| `TUOYU_TENANT_ENABLED`、`TUOYU_TENANT_CONTEXT_SECRET` | 新增，可选：多租户默认关闭；开启时密钥必填 |
| `TUOYU_SHUTDOWN_OFFLINE_DELAY`、`TUOYU_SHUTDOWN_TIMEOUT`、`TUOYU_DUBBO_SHUTDOWN_WAIT`、`TUOYU_DUBBO_TIMEOUT` | 新增，可选：优雅停机的等待时长与 Dubbo 超时（ADR 0007） |
| `TUOYU_SNAILJOB_ADMIN_PASSWORD` | 新增：SnailJob 管理员 admin 的口令（至少 8 位）。仍是默认口令 `admin` 时启动会改为它；**生产环境不设置时 SnailJob 服务端拒绝启动**（`GenerateEnv` 生成的 `.env` 已包含） |
| `TUOYU_ADMIN_INITIAL_PASSWORD` | 新增：管理员 admin 的初始口令（至少 8 位）。admin 仍是种子数据中公开的口令时，tuoyu-system 启动时改为它；口令改过后不会覆盖；**生产环境 admin 仍是种子口令且不设置时拒绝启动**（`GenerateEnv` 生成的 `.env` 已包含） |
| `TUOYU_SQL_LOG_ENABLED` | 新增，可选：完整 SQL 日志（输出每条 SQL 的参数值），**默认关闭**（原来默认开启）；本地调试需要时在 `.env` 中设为 `true`，生产环境开启时启动自检 P9 拒绝启动 |
| `TUOYU_CONFIG_DIR`、`TUOYU_CORS_ALLOWED_ORIGINS`、`TUOYU_SNAILJOB_SERVER_HOST` | 新增，可选：只用于单体（配置目录、跨域来源、SnailJob 服务端地址） |
| 其余 `TUOYU_*` | 见 `.env.example` 中的说明；缺少必填变量时服务拒绝启动并列出缺少的变量（启动自检 C1） |

## 2. Nacos 配置

`deploy/config/nacos` 下的配置都有改动，需要**覆盖导入**（导入前确认命名空间）：

```bash
java tools/nacos/ImportNacosConfig.java              # 预览
java tools/nacos/ImportNacosConfig.java --apply --overwrite
```

主要变化：

- 免登录白名单 `security.ignore.whites` 从 `tuoyu-gateway.yml` 移到 `application-common.yml`（网关与各服务共用）；
- `user.password.*` 改为 `tuoyu.auth.*`（登录失败锁定、验证码、客户端校验）；
- 删除 `api-decrypt.*`，新增 `tuoyu.api-crypto.*`；
- 新增分页、请求大小、上传、Excel 行数上限，`tuoyu.auth.password.bcrypt-cost`，`tuoyu.tenant.*`；
- `datasource.yml` 按 `TUOYU_DB_TYPE` 拼出连接地址并选择驱动；
- 白名单新增 `/resource/email/code`；新增优雅停机（`server.shutdown`、`tuoyu.shutdown.*`）与就绪探针；Dubbo 超时从公共配置移到框架内置的 `common-dubbo.yml`；`tuoyu-gateway.yml` 的负载均衡缓存改为 3 秒；
- 新增 `tuoyu-boot-all.yml`：只用于单体，微服务方式导入也无妨；
- `tuoyu-job.yml` 中执行器的命名空间 `snail-job.namespace` 由 `public` 改为随环境（`${spring.profiles.active}`，与 tuoyu-job 库种子数据中的 `dev`、`prod` 对应）；
- 自己改过的配置项，覆盖导入后要重新改回。

## 3. 数据库

1.0 开始由 Flyway 管理 MySQL 与 PostgreSQL 的表结构（`docs/adr/0004-数据库迁移.md`）。已有数据库**第一次**启用前：

1. 按日期顺序执行 `deploy/sql/upgrade` 下对应数据库的升级脚本（`20261024-menu`、`20261024-gen`），使库达到 V1 基线；
2. 启动 `tuoyu-system`、`tuoyu-workflow`、`tuoyu-snailjob-server`：各自按基线 1 接入，并自动执行 V2 起的迁移（`tuoyu-cloud` 库目前到 V6：删除“批量强退”按钮；多租户的 `tenant_id` 字段、租户表与菜单；修正“流程设计”菜单的权限码；删除“流程表达式定义导出”按钮；删除演示账号 `test`、`test1`）；
3. 接入前服务会核对 V1 中的表是否都已存在，缺少时拒绝启动并列出缺少的表。
4. 使用定时任务时，在 tuoyu-job 库把执行器令牌的占位值改为 `.env` 中的 `TUOYU_SNAILJOB_TOKEN`（`java tools/secrets/GenerateEnv.java` 生成 `.env` 时会打印这条语句；用 `deploy/docker` 下的 compose 部署时由一次性任务 `snailjob-token-init` 自动执行）：

   ```sql
   UPDATE sj_group_config SET token = '<TUOYU_SNAILJOB_TOKEN>' WHERE token = 'SJ_REPLACE_WITH_TUOYU_SNAILJOB_TOKEN';
   ```

**Oracle** 不在 1.0 的 Flyway 支持范围内：按日期顺序执行 `deploy/sql/upgrade` 下全部 `oracle_*.sql`（含 `20261028-menu`、`20261029-tenant`、`20261029-perms`、`20261030-menu`、`20261101-users`）。

注意：此前的开发版本中 Flyway 实际没有执行任何迁移（迁移目录中的 `{vendor}` 没有被替换），库中可能已有一张空的 `flyway_schema_history`。这种情况下新版本会从 V1 开始执行；**已有数据的库**启动前请先删除这张空表，让服务按基线 1 接入。

## 4. 行为变化

| 变化 | 影响 |
|---|---|
| 各服务自行校验登录 | 不经过网关、直接请求服务的 HTTP 调用，原来只需要 same-token，现在还必须登录（白名单中的路径除外） |
| 登录失败锁定 | 账号 10 分钟内失败 5 次、同一 IP 10 分钟内失败 20 次时锁定 10 分钟 |
| 分页 | 未传 `pageSize` 时默认 10 条，最多 500 条 |
| 上传 | 只允许白名单中的扩展名，并校验文件头；上传请求的上限取整个请求与单个文件上限中较小的（默认 50MB），网关直接返回 413 |
| 跨服务异常 | 框架异常（`ServiceException` 等）连同错误码原样传回调用方，原来会被包装成普通异常；调用方没有的异常（如数据访问异常）只传回错误编号，详细信息记在提供方日志中 |
| 演示账号 | 种子数据中的 `test`、`test1`（口令 666666）由迁移 V6 删除，演示角色保留；仍在使用的话请先另建账号 |
| 第三方账号绑定 | 绑定列表接口不再返回第三方平台的令牌、授权码与签名密钥；应用 ID 或密钥未填写的平台视为未配置，绑定与第三方登录提示不支持 |
| 用户角色 | 新增、修改用户时角色可以为空；修改时传空数组表示清空全部角色（与“分配角色”一致），不传表示不修改 |
| 字段加密 | 改为 GCM（`ENC_v2:` 前缀），旧的 ECB 密文仍可用旧口令解密 |
| 生产环境启动自检 | 不安全的配置会拒绝启动；只能用 `tuoyu.selfcheck.skip=P4,...` 按编号跳过 |
| 接口权限 | 参数按键名查询、字典类型下拉、用户导入模板改为需要对应的权限码；只能解绑本人的第三方绑定 |
| 工作流 | Warm-Flow 设计器接口需要流程定义的查询或修改权限，内置表单办理接口不再开放；审批记录、流程图只对流程参与人与流程管理员开放；办理时选人改用 `/system/user/options` |
| 微服务的可执行 jar | 改名为 `target/<模块>-exec.jar`，自己的部署脚本要同步修改 |
| 镜像 | 自有镜像以 UID 1000 运行，挂载的目录要允许它写；网关镜像端口改为 8081；`deploy/docker/docker-compose.yml` 由 `compose-core.yml` 等三套文件取代 |
| 日志格式 | 每行多一个 `[traceId]` 字段，按固定列解析日志的脚本需要调整 |
| 日志配置文件 | 各服务的 logback 配置改名为 `logback-spring.xml`（原 `logback-plus.xml`），`logging.config` 随之修改。**必须先覆盖导入 Nacos 配置再启动服务**：Nacos 中仍是旧文件名时，日志系统初始化失败，服务无法启动。自己挂载或覆盖了 `logback-plus.xml` 的部署要同步改名 |
| 停机 | 默认最长约 55 秒，容器的停止宽限期要相应调大（compose 为 60 秒）；Dubbo 只由 Spring 关闭，不再注册 Dubbo 自己的 JVM 停机钩子 |
| 网关 | 下游服务没有可用实例时返回 503“服务暂不可用，请稍后再试”（原来是 404“服务未找到”） |
| 日志级别 | 业务异常、参数校验失败、没有权限、登录过期等改为 WARN；按 ERROR 告警的规则会少报这些情况 |
| 安全中心 | 汇总各服务的启动自检结果：每个服务启动后把结果写入 Redis（键 `global:selfcheck:<服务名>`），按 `tuoyu.home.services` 读取；接口 `/system/security/overview` 的返回结构相应调整（`service`、`checkedAt` 改为 `sources`，每项检查增加 `services`） |
| 监控接口的前缀 | 前端调用 system 的监控接口（操作日志、登录日志、在线用户、缓存监控、安全中心）改用 `/monitor/...`。微服务中 `/system/...` 仍可访问，单体中只有 `/monitor/...`；自己写的前端或脚本按同样的方式修改 |
| 多租户 | 停用、删除租户时，该租户已登录的会话随即下线；修改默认租户时忽略过期时间与用户数上限，并清除已有的值 |
| 菜单树接口 | `/system/menu/treeselect` 有菜单查询、角色新增或角色修改权限之一即可访问，`/system/menu/roleMenuTreeselect/{roleId}` 有菜单查询或角色修改权限之一即可访问，并校验该角色在当前用户的数据范围内 |
| 未登录的提示 | 401 的 `msg` 改为固定提示（例如“登录已过期，请重新登录”“登录状态异常，请重新登录”），不再是 Sa-Token 的原始消息；按 `msg` 文本判断的前端或脚本需要调整，按 `code` 判断的不受影响 |
| logback | 不再定时重新加载配置文件（去掉 `scan`），修改日志配置后需要重启服务 |
| SnailJob、SnailAI 服务端 | Actuator 默认只暴露 `health`、`info`、`prometheus`，健康检查不展示细节（原来全部暴露）；本地需要时在 `.env` 中设置 `TUOYU_ACTUATOR_EXPOSURE`、`TUOYU_HEALTH_SHOW_DETAILS` |

## 5. 自己写的业务模块

如果在基线版本上新增过业务模块，需要按以下规则调整（ADR 0005）：

- **跨模块调用**：去掉 `@DubboReference`，改为普通的构造器注入；去掉实现类上的 `@DubboService`，契约接口加 `@RemoteApi`（放在 `tuoyu-api-*` 中）；去掉启动类上的 `@EnableDubbo`。业务代码中不能再出现 Dubbo（ArchUnit 检查）；
- **Dubbo 的 mock、stub** 不再支持：需要容错的调用用 `RemoteFallback`；
- **接口权限**：每个接口都要带 `@SaCheckPermission`、`@SaCheckRole`、`@SaCheckLogin` 或 `@SaIgnore`（守护测试检查）；
- **迁移脚本**：放在 `db/migration/<库名>/{vendor}` 下，服务的 `application.yml` 中写 `tuoyu.flyway.database`；
- **单体**：新增的业务模块要加进 `tuoyu-boot-all` 的依赖（同样排除 Dubbo、Nacos、Seata）、启动类的扫描包、`tuoyu-boot-all.yml` 的 URL 前缀表与数据源路由；
- **参数校验** 由提供方负责：实现类加 `@Validated`，接口参数加 `@Valid`；
- **数据权限** 的 SpEL 中，`#user` 由 `LoginUser` 改为 `CurrentUser`（字段 `userId`、`userName`、`deptId`、`deptName`、`tenantId`）；
- `tuoyu-common-mybatis` 不再间接带入 Sa-Token 与 `tuoyu-api-system`，用到它们的模块要直接声明依赖；
- 用到数据权限中“自定义”“部门及以下”范围的服务，要依赖 `tuoyu-common-service-impl`；
- **多租户**（如需开启）：按租户隔离的实体继承 `TenantEntity`，表增加 `tenant_id`；后台任务用 `@TenantJob` 或 `TenantHelper` 明确租户（ADR 0006）；
- **自己实现的 `ContextPropagator`**：跨线程时改为调用新增的 `captureLocal` / `restoreLocal`（默认等同 `capture` / `restore`，不需要修改；跨线程不需要签名或有效期的，可以覆盖这两个方法）。

## 6. 前端

需要使用新前端（`tuoyu-cloud-frontend`）。旧前端的登录与新的接口加密方案不兼容。
