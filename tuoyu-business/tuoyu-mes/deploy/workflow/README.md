# 制造执行的审批流程

制造执行（MES）的两类单据可以接入工作流审批，默认关闭，关闭时单据照常直接流转：

| 审批 | 流程定义文件 | 流程编码 | 开关 | 需要审批的单据 |
|---|---|---|---|---|
| 不良处置评审 | `mes_defect_disposition.json` | `mes_defect_disposition` | `tuoyu.mes.approval.defect-disposition.enabled` | 处置方式为让步接收、报废的不良记录（返工照常直接处置） |
| 补料申请 | `mes_material_supplement.json` | `mes_material_supplement` | `tuoyu.mes.approval.supplement.enabled` | 类型为补料的领退料单（领料、退料照常直接提交） |

两个流程都是“开始 → 申请人 → 审批 → 结束”，审批节点可以通过、退回（回到申请人）或终止。

## 单据怎样流转

- **不良记录**：处置时选择让步接收或报废，单据从“待处置”变为“审批中”；审批通过后执行处置，变为“已处置”。
  被退回、撤销、终止、作废后回到“待处置”，可以重新处置（换成返工则直接处置）。
- **补料单**：提交后从“草稿”变为“审批中”；审批通过后变为“已提交”，仓库才能执行。
  被退回、撤销、终止、作废后回到“草稿”，可以修改后重新提交。审批中的补料单不能修改、取消，仓库不能执行。
- 每次状态变化都记在单据的状态履历中，原因里带审批意见。
- 单据列表中“查看审批”打开审批记录与流程图（只对发起人、办理人、抄送人与流程管理员开放）；审批中的单据，发起人可以“撤销审批”。
- 被退回后，发起人也可以在“我的待办”中直接重新提交，单据随之回到“审批中”。

## 启用步骤

1. **导入**：以有流程定义导入权限的账号登录，打开“工作流 → 流程定义”，选择一个分类后点“导入”，
   分别导入本目录下的两个文件。
2. **调整办理人**：导入后审批节点的办理人是“超级管理员”角色（种子数据中的角色）。在流程设计中把它改为实际的审批角色或人员，
   例如质量主管、生产主管；开启了多租户时，各租户要在自己的租户中导入，并选择本租户的角色。
3. **发布**：在流程定义列表中发布这两个流程。只有已发布的流程才能发起，未发布时提交会提示
   “未找到已发布的流程定义 …，请先在“流程定义”中导入并发布”，单据保持原状态。
4. **打开开关**（流程编码与导入的一致时不用改 `flow-code`）：

   ```yaml
   tuoyu:
     mes:
       approval:
         defect-disposition:
           enabled: true
           flow-code: mes_defect_disposition
         supplement:
           enabled: true
           flow-code: mes_material_supplement
   ```

   - 微服务：写在 Nacos 的 `tuoyu-mes.yml` 中（仓库中的 `deploy/config/nacos/tuoyu-mes.yml` 有同样的示例，默认为 false），重启 tuoyu-mes。
   - 单体：tuoyu-boot-all 不读取 `tuoyu-mes.yml`，写在 `tuoyu-boot-all.yml` 中，重启单体。

关闭开关后，新提交的单据直接流转、不发起审批；已经在审批中的单据仍按 `flow-code` 接收审批结果，所以关闭开关时不要改流程编码。

## 审批结果怎样回到单据

工作流在审批有结果时发布流程事件，tuoyu-mes 只处理上面两个流程编码的事件：

- 单体中工作流与 MES 在同一进程，事件在工作流的事务提交后处理；
- 微服务中事件经消息总线（默认 Redis Stream，与工作流服务使用同一个 Redis）投递到 tuoyu-mes。tuoyu-mes 停机期间的事件在它启动后补投；
  第一次部署 tuoyu-mes 之前的事件不会投递。

事件按单据当前的审批（业务 ID）匹配并带状态条件更新，重复投递不会重复处理。

## 注意

- 不要在“流程实例”中直接删除审批中的流程实例：删除不会通知 MES，单据会停在“审批中”。需要放弃时请撤销审批或作废流程实例。
- 修改流程时保持“申请人”是开始后的第一个节点，否则无法发起。
